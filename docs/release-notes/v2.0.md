# School Ops v2.0 — Re-engineering & Migration

Re-engineering release produced on `feature/reengineering` (SEN 401, Lab 4).
**Breaking change:** the console scripts `app.py` / `students.py` are replaced by a REST API.

## Reverse engineering
- `tools/analyze.py`: AST-based static analysis (modules, classes, functions, dependencies, side effects).
- `docs/lab4/reverse-engineering.md`: function inventory, dependency and UML class diagrams, 8 code-smell findings, target architecture.

## Refactor & modularise
- Student Records (Labs 1–2) and Inventory (Lab 3) merged into one `app/` package:
  `models`, `services`, `utils`, `sources`, `repository`, `database`, `controllers`.
- DRY: four duplicated highest/lowest helpers became the generic `highest_by` / `lowest_by`;
  one generic `Repository` serves both tables.
- Docstrings and type hints throughout (Python 3.12 generics).

## Data / API migration
- `scripts/migrate.py` moves `data/students.json` and `data/inventory.csv` into SQLite
  in one transaction and checks counts and totals afterwards.
- FastAPI REST endpoints for students and inventory (CRUD + statistics), with OpenAPI docs at `/docs`.

## Docker Compose deployment
- `Dockerfile` (API, non-root) and `client/Dockerfile` (report client).
- `docker-compose.yml`: `migrate` → `api` (health-checked) → `report`, sharing a named volume for SQLite.
- CI now builds and runs the full stack on every PR.

## Tests
32 tests: unit tests for utils/services/models and end-to-end API tests against a migrated database.
